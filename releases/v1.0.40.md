# v1.0.40

Field-tested in production, running stable.

## Multi-board support

- New `esp32-wroom32` PlatformIO environment for plain ESP32-WROOM-32 boards (no PSRAM), alongside the existing `esp32dev` environment for the ESP32-S3 N16R8. Same firmware, no code differences — just board config (`pio run -e esp32-wroom32`).
- `esp32-wroom32` uses a single 3MB app partition (`huge_app.csv`) instead of the default dual ~1.25MB OTA slots, which left almost no headroom for the firmware to grow. Trades the dual-slot OTA rollback safety net for breathing room — a fair trade here, since cable reflash is already the only update path on this board (see next point).
- The Web UI's Update page is now hidden and blocked (client- and server-side) on boards without PSRAM, since the combined-package upload buffer requires it. The About page now shows PSRAM presence/size to every viewer, not just admins, so it's obvious at a glance which board you're on.

## Fixed: user credentials were reset on every boot

Found and fixed a real bug: password changes never survived a reboot. The code that was supposed to restore previously-saved user accounts from `config.json` on boot only *parsed* the stored username/salt/hash — it never actually applied them, so the in-memory user list came up empty every time and got silently recreated from the factory defaults (`admin`/`admin1234`, `user`/`user1234`), overwriting whatever password you'd actually set. This also re-ran the PBKDF2 hash (100,000 iterations, twice) on every single boot instead of only the first, adding several real seconds to every startup. Now fixed: stored credentials are restored as-is, and that cost is paid once, on first boot only.

## New: momentary/pulse relays

`Relay` components can now be configured as momentary (`Setup.PulseTimeMs`, 20–5000ms): turning one on auto-releases it after the configured time, instead of latching — for driving something that expects a brief button press, like the contacts on a cloned RF remote, rather than a held contact. Configurable from the Web UI's component editor or `comp set <relay> pulsetimems=<ms>`.

## New: Button gets a `Changed` event

`Button` components now fire `Changed` on any state transition (press or release), matching what `Relay`, `Blinds`, and `Thermometer` already had. Available in automation bindings, MQTT discovery, and the CLI.

## MQTT / Home Assistant

- Removing a component (`comp remove`, CLI or Web UI) now actively unpublishes its Home Assistant discovery entries, so it actually disappears from HA instead of lingering as a stale/unavailable entity.

## Web UI

- Every page now shows which device you're on: the hostname appears in the browser tab title (`DeviceIQ [hostname] - Page`) and, in bold, next to the username in the topbar — useful once you have more than one DeviceIQ on the network.
- Dashboard: toggle between a flat grid and grouping components by class, plus a configurable refresh interval (500ms/1s/3s/5s, default 1s — previously a fixed 3s). Both preferences are remembered per browser.
- Dashboard and the component editor now show each component's ID (`#N`) next to its name.
- Session idle-timeout warning: the Web UI now warns (and logs out client-side) shortly before the same idle timeout the server already enforced silently — previously you'd only find out on your next click.
- Config export now downloads as `config-<hostname>.json` instead of a fixed `config.json`.
- Restart moved out of the header (was next to Sign Out on every page) into Settings → Configuration → Tools, alongside Restore Factory Defaults.

## Configuration format

- `data/config.json` is no longer shipped in the repository/filesystem image — it previously carried real-looking Wi-Fi and MQTT credentials that would've been flashed as-is onto every new device. A device with no `config.json` now generates one from scratch on first boot, same as before, but without inheriting someone else's example credentials.
- Removed the `Update` and `Orchestrator` config sections entirely — confirmed unused anywhere in the firmware (no CLI, Web UI, or runtime code referenced them).
- `Hostname` now accepts dotted, multi-label names (RFC 1035, up to 255 chars) instead of a single label — useful for names like `office.deviceiq`.
